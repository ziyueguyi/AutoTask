# 淘宝扫码登录可行性

对应脚本：`tx_login_standalone.py`。操作细节见 [淘宝扫码自动化流程.md](淘宝扫码自动化流程.md)。

## 结论

**可行，但只适合重点账户续 Cookie，覆盖不了全量账号。必须用真机，模拟器不行。**

一台 Windows 脚本机出码，ADB 推到真机「淘系」相册，uiautomator2 驱动淘宝扫码确认，脚本再轮询并收集 Cookie。已跑通，不依赖 Appium，也不需要两台电脑。

通过该方式登录后，可正常拿到 Cookie，并能跳转到商家后台。Cookie 有效期超过一天。

## 已验证

- 扫码登录可跑通，Cookie 写入 `tx_login_cookie.txt`
- 该 Cookie 可进入商家后台
- Cookie 有效期超过一天（过期后再扫即可）
- 手机淘宝扫 PC 码不会把手机踢下线（多点登录）
- 单台机可同时挂两个号：【淘宝 + 淘宝特价版】，两路 Cookie 互不影响。其他淘系应用暂未测试

## 未通过 / 未尝试

- 模拟器测试未通过：App 有模拟器检测，不能用模拟器当扫码器
- 同一 App 多开未尝试

## 范围

一台真机当扫码器，一次确认一号，适合把少数重点号的 Cookie 续上。无法让所有账号都走这套登录。

风控、改密、某端主动退出，不在多点登录保证范围内。

## 流程

1. **出码**：登录页取 `_csrf`，`generate.do` 拿 `codeContent` / `t` / `ck`，本地渲染二维码（H 级纠错，中间嵌淘宝图标），保存 `tx_login_qr_final.png`。
2. **进相册**：ADB 直接 push 到 `/sdcard/Pictures/淘系/`，MediaStore 用 `_display_name` 插入并广播扫描。不要先推 Download 再删。
3. **扫码**：淘宝首页 `content-desc="扫一扫"` → 相册 → 淘系 → 按文件名点图 → 「确认登录」。确认前不要 force-stop / `am kill-all`。
4. **收尾**：清空淘系相册，等 4 秒，只 `am force-stop com.taobao.taobao`。
5. **收 Cookie**：`query.do` 间隔 5s、超时 170s；`CONFIRMED` 立即停。收集 Set-Cookie、`asyncUrls`、回跳首页、补 `_m_h5_tk`。打印完整串并写入 `tx_login_cookie.txt`。

## 多点登录

手机淘宝保持登录去扫 PC 码，拿到的是另一路 Web/PC Cookie，和手机会话并存。

- 手机可以长期挂着登录态当扫码器，不必每次扫完再登手机
- 脚本 `force-stop` 只关进程，不是服务端踢会话
- `--force-login` 只清脚本机本地 session，不动手机、不踢其它端

多点登录（手机 + PC Cookie 并存）已验证。同一 App 多开未尝试，不要和「淘宝 / 淘宝特价版各登一号」混为一谈。
